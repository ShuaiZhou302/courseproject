\begin{abstract}
Contact-rich, dynamic in-hand skills such as pen spinning remain difficult to transfer from simulation. PenSpin~\citep{wang2024penspin} improved its hardware performance by fine-tuning a proprioceptive student on a small set of successful open-loop replays. We ask whether the same limited target experience can instead improve the contact observations used during simulator training. We propose to replay source actions in a target simulator, learn a mapping from source link-level contact to target contact, freeze that mapping in the source simulator, and re-distill a contact-aware student. Isaac Gym~\citep{makoviychuk2021isaac} supplies source training; Project SuperDex~\citep{superdex2026} supplies a controlled target with observable contacts. We compare against the original proprio-only student, raw-contact training, randomized contact, simple calibration, and PenSpin-style target fine-tuning. This sim-to-sim proxy tests the value of contact-observation alignment; it does not claim to correct contact dynamics or establish hardware transfer.
\end{abstract}
\keywords{Dexterous manipulation, contact alignment, sim-to-sim transfer}

\section{Introduction}

Simulation-based reinforcement learning has enabled in-hand manipulation skills that are hard to teleoperate~\citep{qi2022hora,openai2020dexterous,qi2023general}. Pen spinning is a demanding case: it is fast, contact-rich, and unforgiving of small timing errors. PenSpin~\citep{wang2024penspin} trained a privileged oracle and distilled a student using proprioception alone. Its sim-trained student did not transfer reliably to hardware, even after substantial simulation work.

PenSpin's adaptation replayed oracle actions open-loop on hardware, retained successful trajectories, and fine-tuned the student. This uses little target data, but it adapts a particular policy rather than improving the contact observations available in the training simulator. We investigate whether replay data can be used at the observation level, so a policy can continue learning from target-like touch cues in the source simulator.

Prior work has adapted simulator parameters from target experience~\citep{chebotar2019closing,he2025asap,ramos2019bayessim}, and recent work has calibrated tactile simulation through replay~\citep{real2sim2real2026}. Our proposed intervention is narrower: it aligns a policy's contact input while leaving the source collision solver, friction, and object motion unchanged. Because PenSpin's original student has no contact input, we explicitly add a contact-aware student and retain the original proprio-only student as a baseline.

We evaluate this idea in a sim-to-sim setting, with Isaac Gym as the source and SuperDex~\citep{superdex2026} as the target. The target simulator permits contact labels and controlled resets that are difficult to obtain on hardware. We can vary friction and compliance, measure state divergence during paired replays, and evaluate every policy on matched target initial states. The setting is a controlled proxy, not a real-world result.

We ask three questions:
\begin{enumerate}[label=\textbf{RQ\arabic*:},leftmargin=*]
  \item Under changes in target friction and compliance, when does a contact input help or hurt transfer relative to proprioception alone?
  \item How much target performance does a learned contact observation mapping recover from a small replay dataset?
  \item How does observation alignment compare with target-policy fine-tuning at the same number of replay attempts?
\end{enumerate}

\section{Method}

We retain PenSpin's privileged oracle, reproduce its proprio-only student, and add a student with binary link-level contact. The proposed third stage aligns that contact input and re-distills the contact-aware student (Figure~\ref{fig:pipeline}). We call Isaac Gym the source domain $\src$ and SuperDex the target domain $\tgt$.

\paragraph{Setup.}
An Allegro hand spins pen-like objects using PenSpin's released task, action space, and PD control. The common observation $c_t\in\{0,1\}^{K}$ indicates which of $K$ corresponding hand links touch the pen. Source contact forces and pooled target readings are thresholded at the same policy observation rate. Link mapping and thresholds are fixed using training and validation replays, never target test episodes. We aim to match object geometry, action timing, initial-state distribution, and rotation/drop criteria across simulators.

\begin{figure}[htbp]
\centering
\input{figures/pipeline}
\caption{Six-stage pipeline. Paired replay attempts train the contact observation mapper $f$; source-domain rollouts train the student. The target simulator supplies native contact for evaluation, while target-policy fine-tuning is a separate baseline.}
\label{fig:pipeline}
\end{figure}

\begin{enumerate}[leftmargin=*]
  \item \textbf{Oracle.} Train a privileged PPO oracle in $\src$ with object state and physical parameters, following PenSpin's reward and control setup.
  \item \textbf{Student.} Reproduce the proprio-only student and distill a separate contact-aware student from the same oracle. The latter observes a history of proprioception $q$ and binary contact $c_{\src}$.
  \item \textbf{Replay and collect.} From matched initial states, replay the same oracle actions open-loop in $\src$ and $\tgt$. Log contact, joint and object state, and preceding actions in both domains. All attempted replays supply contact labels, including failures; the fine-tuning baseline may filter successes.
  \item \textbf{Contact alignment.} Train a small temporal mapper to predict target binary contacts from source observations available before action $a_t$:
  \begin{equation}
    p_{\tgt,t}=f_{\phi}(c_{\src,t-H:t},q_{\src,t-H:t},a_{t-H:t-1}),
    \quad \mathcal{L}=\operatorname{BCE}(p_{\tgt,t},c_{\tgt,t}).
  \end{equation}
  Choose a per-link threshold $\tau$ on validation replays and form $\tilde c_{\src,t}=\mathbf{1}[p_{\tgt,t}>\tau]$.
  \item \textbf{Re-distill.} Freeze $f$ and distill the contact-aware student again from the fixed oracle in $\src$, supplying $\tilde c_{\src}$ in the same binary format as target contact.
  \item \textbf{Deploy.} Evaluate the re-distilled student in $\tgt$ with native binary target contact. The mapper is not run in $\tgt$.
\end{enumerate}

Time-indexed open-loop replays can drift into different physical states. We will measure joint- and object-state divergence and report contact prediction accuracy by divergence bin. In a separate diagnostic, we reset $\tgt$ to source states before matched steps to create state-matched contact pairs. This requires privileged simulator access and is neither a deployable hardware-data baseline nor a mathematical upper bound.

\paragraph{Metrics.}
Policy metrics are full rotations, time until drop, and success rate at a fixed rotation criterion. Sensor metrics on held-out replay attempts are per-link contact precision, recall, F1, and onset timing error. We will report mean and variability across evaluation seeds together with replay-state divergence.

\paragraph{Data efficiency (RQ2, RQ3).}
We compare 10, 25, 50, and 100 attempted target replays. Calibration and alignment can use labels from all attempts. PenSpin-style fine-tuning filters successful trajectories as in the original method, so we will report its successful demonstration count at each equal-attempt budget. Training, validation, and contact test sets are split by entire replay, not by time step.

\paragraph{Diagnostic comparisons (RQ1).}
We compare each student's source and target performance, then vary target friction and compliance. Proprio-only transfer, raw-contact transfer, and aligned-contact transfer show which interventions help. Observation errors and contact dynamics interact, so their performance differences are not additive estimates of separate gap components. The state-matched control tests whether time-indexed pairing error limits the mapper.

\section{Plan}

The largest engineering risk is porting the Allegro/pen environment to SuperDex. We begin with a short hand-control/contact replay smoke test before scaling data collection.

\begin{itemize}[leftmargin=*]
  \item \textbf{10/09--10/23:} Reproduce the PenSpin oracle and proprio-only student; implement and validate the shared link-level contact representation.
  \item \textbf{10/24--11/06:} Port the Allegro hand, pen, and PD controller to SuperDex; match control timing and collect paired replay attempts.
  \item \textbf{11/07--11/20:} Train the contact mapper, re-distill the contact-aware student, and obtain first zero-shot target results.
  \item \textbf{11/21--12/04:} Run equal-attempt baselines, data-budget sweeps, friction/compliance variations, and state-matched diagnostics.
  \item \textbf{12/05--12/11:} Prepare the final report and presentation.
\end{itemize}

\paragraph{Fallbacks.}
If full pen spinning is unstable in the port, we will first test a simpler in-hand rotation task~\citep{qi2022hora}. If the SuperDex port stalls, we will use a target simulator with explicit link-level contact labels and state the change. If the target gap is too small, we will widen it through controlled friction and compliance changes. These outcomes would remain simulation evidence rather than hardware transfer.
