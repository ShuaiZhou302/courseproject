\begin{abstract}
Dynamic in-hand pen spinning is difficult to transfer across simulators and to hardware because small contact errors can change the trajectory. PenSpin~\citep{wang2024penspin} addressed its hardware gap by fine-tuning a proprioceptive student on a small set of successful open-loop replays. We instead test whether the same replay attempts can align a source simulator's contact observations with a target simulator's tactile readings, then re-distill a contact-aware student in the source simulator for zero-shot deployment. Isaac Gym~\citep{makoviychuk2021isaac} supplies training and Project SuperDex~\citep{superdex2026} serves as a target simulator with observable contact, allowing direct sensor-level evaluation. This controlled sim-to-sim study measures whether observation alignment improves transfer while separately diagnosing the effects of state drift and contact dynamics; it does not claim to correct the physics or establish real-world transfer.
\end{abstract}
\keywords{Dexterous manipulation, tactile alignment, sim-to-sim transfer}

\section{Introduction}
Pen spinning is a fast, contact-rich manipulation task in which small changes in timing can cause a drop. PenSpin~\citep{wang2024penspin} trained an oracle with privileged state in Isaac Gym and distilled a student that used \emph{proprioception only}. Its sim-trained policy did not transfer reliably to hardware; fine-tuning on fewer than 50 successful hardware replays improved performance. That target data adapted the policy, leaving open whether a small dataset could instead improve the contact observations available during source-domain training.

We study that question in a controlled sim-to-sim proxy: Isaac Gym is the source domain $\src$ and SuperDex~\citep{superdex2026} is the target domain $\tgt$. Related work adapts simulation from target experience~\citep{chebotar2019closing,he2025asap,ramos2019bayessim}, including tactile event calibration~\citep{real2sim2real2026}. Our intervention changes the student's \emph{contact input}, not the source collision solver, friction, or object motion. The target simulator permits contact labels and controlled state resets that would be difficult to obtain on hardware.

We ask: (RQ1) Under controlled changes in friction and compliance, when does contact input help or hurt transfer? (RQ2) Does a learned contact observation mapping improve zero-shot target performance with few replay attempts? (RQ3) How does it compare with target-policy fine-tuning at the same number of replay attempts?

\section{Method}
We retain PenSpin's privileged oracle but explicitly change its second stage: alongside a reproduced proprio-only student, we distill a student with binary link-level contact. The proposed third stage learns a contact mapping from replay data and re-distills that contact-aware student in $\src$ (Figure~\ref{fig:pipeline}).

\paragraph{Environment and reward.}
An Allegro hand spins pen-like objects using PenSpin's released task, action space, and PD control. We retain its oracle reward: clipped angular velocity about the commanded axis, with penalties for excess velocity, object translation/position error, hand-pose deviation, torque, and mechanical work. Source and target evaluations use the same object geometry, action timing, initial-state distribution, and rotation/drop criteria. Before scaling data collection, a small port smoke test checks hand kinematics, actuator commands, one-step contact readings, and a short replay in SuperDex.

\paragraph{Shared contact representation.}
Let $c_{\src,t},c_{\tgt,t}\in\{0,1\}^{K}$ indicate which of the same $K$ hand links touch the pen. Source contact forces and pooled target tactile readings are thresholded at the corresponding observation time. We fix link mapping and sampling convention before training and select thresholds using training/validation replays, never target test episodes.

\paragraph{Replay and supervision.}
From matched initial states, replay the oracle's action sequence open-loop in both simulators and record $(q_{\src,t},c_{\src,t})$, $(q_{\tgt,t},c_{\tgt,t})$, object state for offline diagnostics, and the preceding actions. All attempted rollouts supply contact labels, including failures. Time-indexed contacts need not describe the same physical state after the trajectories drift; we measure joint/object-state divergence and report mapping accuracy by divergence bin. In a separate diagnostic, we reset $\tgt$ to source states before a matched step to construct state-matched contact pairs. This control uses stronger simulator access and is not an attainable hardware-data baseline or a mathematical upper bound.

\paragraph{Alignment and re-distillation.}
A small temporal model outputs target-contact probabilities from source observations available before choosing action $a_t$:
\begin{equation}
p_{\tgt,t}=f_{\phi}\!\left(c_{\src,t-H:t},q_{\src,t-H:t},
a_{t-H:t-1}\right),\quad
\mathcal{L}=\operatorname{BCE}(p_{\tgt,t},c_{\tgt,t}).
\end{equation}
We select a per-link threshold on held-out replay data and feed $\tilde c_{\src,t}=\mathbf{1}[p_{\tgt,t}>\tau]$ to the student during source-domain re-distillation from the fixed oracle. At deployment, the same student receives binary native target contact $c_{\tgt,t}$; $f$ is not run in $\tgt$. We also compare probability input and hard thresholding as an ablation so that a gain cannot be attributed to an unnoticed train/test input mismatch.

\section{Experiments}
All methods use the same target test objects, initial states, and evaluation episodes. We compare proprio-only and raw-contact students, source contact randomization (noise, dropout, delay), parametric contact calibration~\citep{real2sim2real2026}, our learned alignment, and PenSpin-style target fine-tuning~\citep{wang2024penspin}. The state-matched variant is reported as a diagnostic with its extra state access clearly marked.

\paragraph{Data budget and metrics.}
For 10, 25, 50, and 100 \emph{attempted} target replays, calibration and fine-tuning receive the same attempts. Fine-tuning follows PenSpin by filtering for successes; we report how many successful demonstrations each budget yielded. Policy metrics are full rotations, time to drop, and success rate at a fixed rotation criterion. Sensor metrics on held-out replay attempts are per-link precision, recall, F1, and contact-onset timing error. We report mean and variability across evaluation seeds, plus replay-state divergence.

\paragraph{Diagnostic comparisons (RQ1).}
Compare each student's source and target performance, then vary target friction and contact compliance. Proprio-only transfer and aligned-versus-raw-contact transfer reveal which interventions are useful, but observation and dynamics interact; their performance differences are not additive estimates of separate gap components. The state-matched control tests whether time-indexed pairing errors account for poor alignment.

A gain in this proxy setting would support contact-observation alignment, not real-hardware transfer or a correction to contact dynamics.
